## 1、项目 / 产品经验（68 题）

### 1-1　请介绍一下你做的比较好的项目

1. 选择一个有明确业务结果的项目，用“背景—目标—个人职责—方案取舍—过程—结果—复盘”讲述。先描述用户和痛点，而不是堆技术名词。
2. 说明你为什么选用 AI、为什么不用规则或人工方案，标明最关键的模型、知识库、产品流程和异常兜底。
3. 结果必须区分你的贡献与团队贡献，给出真实的使用量、任务成功率、成本或效率的前后对比，并解释指标口径。
4. 结尾主动说一个失败案例、改进动作和如果重做会改变什么，这比泛泛说项目成功更能证明能力。

**面试验证：** 如果不用 AI，你是否能以更低成本解决同一个问题？

### 1-2　你为了达成DAU，转化率等业务目标，你的核心动作有哪些？

1. 先把 DAU、留存、转化拆成可观察漏斗：触达→激活→首次有效使用→持续使用→付费/业务转化，并定义去重、时间窗和分母。
2. 用数据定位最大流失节点，再选择引导优化、减少等待、改善答案质量、场景入口和召回提醒等动作，避免同时改太多变量。
3. 每次迭代设定主指标和护栏指标，例如完成率上升时还要观察投诉率与单位成本；采用灰度或 A/B 测试识别增量。
4. 复盘时把自然增长、季节性、渠道变化与产品动作区分开，不能直接把整体 DAU 变化都归因于自己。

### 1-3　知识库是怎么构建的？你做了哪些优化？解决了什么问题？

1. 知识库构建先盘点数据源、责任人和访问权限，经过解析、去重、清洗、分块、元数据标注、向量与关键词索引形成离线链路。
2. 在线链路根据用户身份和问题执行查询理解、权限过滤、混合召回、重排、证据拼接和受约束生成，并给出引用。
3. 优化不是单纯调 chunk 大小：复杂表格用结构化解析，跨段关系用层级检索，版本更新做增量索引和失效清理。
4. 拿有标准证据的评测集测 Recall@K、nDCG、引用正确率、无依据回答率、延迟和成本，以错误归因决定改哪个环节。

### 1-4　你有没有参与过模型选型的工作？具体怎么做的？由你来主导么？

1. 明确模型选型的目标场景、语言、模态、知识更新、部署区域和数据隐私约束，先筛除不满足硬要求的模型。
2. 建立同一评测集和统一提示词，对比任务准确率、工具调用成功率、长上下文稳定性、p95 延迟、吞吐与每次成功任务成本。
3. 评测至少覆盖高频、长尾、危险边界、对抗输入和实际线上样本；不要只看通用榜单。
4. 用小流量影子测试和灰度发布验证，给出回滚阈值；如不是你主导，应清楚区分本人负责的评测、成本分析和最终决策。

### 1-5　你的项目的数据评测集是怎么建的，你从哪些维度保证数据的质量？

1. 先确定业务任务及失败代价，再抽样真实日志、专家构造样本和历史 bad case，按意图、难度、语言、用户群及风险等级分层。
2. 为每个样本保存输入、期望行为、可引用证据、评分标准、标注者与版本；双人标注分歧时由领域专家仲裁。
3. 测试集与开发集隔离，定期查重、防泄漏，纳入拒答、权限越界、信息缺失和工具失败等反例。
4. 发布前用回归集、专家评审、自动评分与线上灰度共同评测，并记录每次模型或 Prompt 变更造成的得失。

### 1-6　你的AI产品，如何衡量大模型上线后的ROI？

1. 先定义 ROI 计算口径：增量净收益除以总投入；收益可来自节约人工、减少差错、提高转化、留存或新增付费，不能把曝光量直接当收入。
2. 成本包含模型 Token、检索/存储、GPU、研发集成、人工标注、监控、审核、运维和合规；区分固定成本、边际成本及迁移成本。
3. 采用非 AI 对照组或上线前基线，并按同等业务量比较；对难以货币化的满意度、质量和风险控制单列指标。
4. 报告乐观/中性/保守情景、回本周期和敏感性分析，以“每成功任务成本”判断是否值得继续扩大投入。

> **技术/指标纠错：** 收益、成本、ROI 必须有可复核口径；满意度提高不等于直接带来等比例营收。

### 1-7　你的产品版本是如何规划的，里程碑事件如何确定？

1. 先明确产品战略、目标客户、商业目标及必须解决的场景，构建机会池并评估价值、紧急性、实施难度和风险。
2. 版本规划按验证顺序：MVP 证明需求与可行性；第二阶段完善质量、稳定性和运维；第三阶段扩展渠道、客户和商业化。
3. 每个里程碑设可交付物、责任人、依赖项和进入下一阶段的门槛，如核心任务成功率、p95 延迟或付费意向。
4. 预留数据、模型和合规不确定性缓冲，版本复盘不是按日期打勾，而是根据证据动态调整优先级。

### 1-8　项目预算缩水，如何保持盈利？

1. 预算缩减时先拆分成本和贡献毛利，识别影响关键客户价值的核心功能与可延期的低优先级工作。
2. 在保底体验前提下做方案降本，例如高频问题缓存、小模型分流、批量处理、低成本模型路由和压缩上下文。
3. 与业务和研发共同计算每项降本动作对质量、交付时间、留存、价格的影响，不能用牺牲核心可信度换短期利润。
4. 必要时收缩目标客户、调整套餐与服务边界，形成重新确认的目标、风险清单和现金流计划。

### 1-9　你在做AI产品的生命周期里有没有什么经验和工具可以复用或提效的？

### 1-10　如何评估小模型是否适合我们的场景？

1. 判断小模型首先要看任务是否边界清晰，例如分类、意图路由、字段抽取、简单审核等，比开放式规划更适合小模型。
2. 做同数据集的成本与效果对比，测精确率/召回率、长尾泛化、吞吐、p95 延迟、部署资源以及量化后的性能下降。
3. 设计级联方案：规则/小模型先处理高置信样本，低置信或复杂任务升级到大模型或人工；校准分流阈值。
4. 关注维护负担和数据漂移，确保小模型不是离线高分、线上误判不断。

### 1-11　我收集到badcase了，然后我也分类了，然后每个类别的badcase我咋优化？

1. 先按事实性、检索、推理、工具、格式、安全和体验分类 bad case，并验证标签之间允许多因并存。
2. 每类都建立“复现—定位—假设—单变量修改—回归”流程：缺知识补数据，召回漏项改切分/检索，排序错误调重排，证据充足仍乱答则调整生成与验证。
3. 不能只凭模型自述归因；必须查看实际 Query、命中片段、工具入参、返回值和最终 Prompt。
4. 建立错误频次×严重度×业务影响的优先级，回归检测修好旧案例是否破坏其他场景。

### 1-12　用户表达一个模糊意图时，助手再次追问，用户可能会补充新的信息，可能提供更加模糊的信息，在这个复杂的多轮对话中，如何记住用户说了什么，除了短期记忆的方法，有没有什么辅助方法来记录每一轮对话中提炼的关键词等？

1. 多轮对话不能只保存完整聊天文本，应维护会话状态结构，包含当前目标、槽位、已确认事实、待澄清点、历史决策和工具执行结果。
2. 每轮做增量状态更新：新信息合并、矛盾项标记、低置信事实追问、过期信息失效；必要时保留原句和来源时间。
3. 长会话采用最近轮次+压缩摘要+按需检索的组合，避免固定轮数造成关键事实丢失。
4. 涉及订单、金额、地址等高风险操作时，从权威系统实时核验，不因历史记忆存在就直接执行。

### 1-13　怎么判断用户意图更改了，是只根据目前用户说的这句话还是根据用户所有上下文？

1. 意图切换要同时看用户当前表述、上文正在完成的任务、指代关系和明确否定词，不能只看最后一句。
2. 状态机区分“补充当前任务”“修改槽位”“暂停后切换”“并行新增任务”和“终止任务”，对模糊情况明确追问。
3. 对于“算了，先查物流”这类话，应暂停退款流程并保留未提交状态；用户返回时再确认关键参数。
4. 以意图切换准确率、错误执行率、澄清轮数和用户纠正率评估策略。

### 1-14　多轮对话，什么样的prompt可以实现多轮意图判断

1. 设计结构化提示词，要求输出当前意图、是否切换、与上一意图关系、已识别槽位、缺失字段和置信度，并限制枚举值。
2. 给出续问、纠正、否定、多个意图并存等少量代表性示例，重点让模型基于完整对话状态判断。
3. 模型输出只作为候选状态更新，业务代码负责 schema 校验、状态转移约束和敏感动作确认。
4. 用真实多轮数据覆盖“把之前的换成明天”“不是这个订单”等反例做离线回归。

### 1-15　让你设计一个系统，如何在智能体和用户对话的过程中，提炼出用户的画像信息

1. 先确定画像用途和最小必要字段，区别用户明确陈述、行为推断与系统核验事实，不要把模型猜测直接存成真相。
2. 在用户知情及适当授权下抽取兴趣、偏好、业务设置，附来源、时间、可信度、保留期限和修改接口。

### 1-18　目前AI的能力还达不到理想状态，不能解决用户真正的需求，商业模式也很难跑通，这种现状下，AI产品经理可以为业务做些什么？

1. AI 能力不成熟时，产品经理更应寻找成本可控、错误可恢复、人工可兜底的高频场景，而非强推全自动。
2. 先算现有流程的单位成本和错误代价，从搜索辅助、文档归纳、草稿生成、决策支持等低风险任务切入。
3. 设计人机协作与置信分层，让用户能纠错、引用来源可追溯，累积高质量反馈数据。
4. 用小样本试点证明真实增量价值；当 AI 劣于规则系统或人工流程时，应该停止或调整方案。

### 1-19　你在做模型评测时遇到过哪些困难？

### 1-23　哪些策略能提升大模型的召回效果？

1. 要提升 RAG 召回，先确认知识本身存在且解析正确；缺失文档时无论怎么调检索都无济于事。
2. 分别改查询侧（纠错、消歧、多查询）、索引侧（结构化分块、元数据、混合索引）和排序侧（融合、重排、去重、邻块扩展）。
3. 为不同任务选择 TopK，不应越大越好：较大候选池可能提升召回却增加噪声与成本。
4. 使用 Recall@K、Hit@K、nDCG、答案支持度和延迟做消融对比，不把召回指标和最终生成准确率混为一谈。

### 3-2　大模型微调和RAG，各自有什么优势？你的决策路径是什么？

### 3-10　降低大模型幻觉有哪些方式

1. 幻觉可能表现为编造事实、引用不存在的来源、数值不一致或无证据却过度确信；应按风险和来源定位。
2. 可通过权威检索、数据库/计算器工具、约束生成、引用校验、拒答和人工复核降低风险，但不能保证完全消除。

### 3-40　请解释RNN原理的 LSTM跟transformer区别在哪里？

### 3-54　MCP 和 Function Calling 的区别是什么？

1. MCP 是用于 AI 应用与外部工具、资源等能力交互的标准协议；Function Calling 是模型输出结构化工具调用请求的机制，两者是不同层次，可以组合。
2. 模型产生工具调用后，宿主应用负责执行与返回结果；MCP 服务器可以承载某些工具的发现和调用能力，但它不替代业务鉴权。
3. 两者都可设计同步或异步执行路径，不能用“MCP 异步、Function Calling 同步”来区分。
4. 工程关键是工具 schema、权限、取消、超时、参数校验、用户确认、审计及错误处理。

> **技术/指标纠错：** MCP 是标准化能力集成协议，Function Calling 是模型向宿主发出结构化工具请求的机制；它们不是“同步/异步”的一对概念。

## 8、薪资谈判（4 题）

### 8-1　面试邀约时，HR问你期望薪资该如何回答？

1. 初次邀约可以先确认岗位职责、级别、工作地点与总体薪酬构成，再给出合理的目标范围或说明愿意根据岗位级别讨论。
2. 提前研究同地区同级岗位行情和个人可接受区间，避免完全不了解公司预算就报极端数字。
3. 既不要虚报现薪，也不必过早披露无法接受的最低底线。
4. 保持合作态度，可说“结合岗位范围与总包结构，我希望在合理市场区间内沟通”。

**面试验证：** 你实际采取的三个动作是什么？哪个指标证明它们有效？

**原题位置：** https://github.com/zxt6991-source/ai-pm/blob/master/ai-pm-job-interview/ai-pm-job-interview.md#L7552

### 8-2　HR最后一面/offer正在流程中，问你期望薪资该如何回答？

1. 接近 Offer 时应先确认固定薪资、绩效、年终、股票、福利、试用期、加班制度及兑现条件，比较全年可预期总包。
2. 把期望与岗位责任、市场水平和自身能力价值联系，而不是仅按上一份工资乘固定涨幅。
3. 给出明确但有依据的目标区间，确认对方预算和决策流程，必要时权衡现金、成长空间与风险。
4. 所有谈好的条件应落实到书面 Offer，不把口头承诺当成确定收入。

**面试验证：** 你实际采取的三个动作是什么？哪个指标证明它们有效？

**原题位置：** https://github.com/zxt6991-source/ai-pm/blob/master/ai-pm-job-interview/ai-pm-job-interview.md#L7566

### 8-3　你的期望薪资有点超出我们的预算，你最低可以接受多少？

1. 当 HR 说超预算时，先询问具体预算结构和不可变限制，了解是固定工资、奖金还是职级限制。
2. 重申期望来自岗位职责、市场薪酬和自己能创造的价值，避免在信息不足时立即报出最低底线。
3. 若确有差距，可讨论职级、奖金、签约金、试用期调薪机制或其他明确书面条款。
4. 如果总包始终低于合理底线，也要有礼貌地接受双方不匹配，不必靠话术强行成交。

**面试验证：** 这个数字的单位、分母、样本量、测量周期和来源分别是什么？

**原题位置：** https://github.com/zxt6991-source/ai-pm/blob/master/ai-pm-job-interview/ai-pm-job-interview.md#L7574

### 8-4　你要的涨幅超出我们公司的要求，我们公司规定最高涨幅不能超过 10%

1. 面对涨幅不得超过 10% 的说法，先区分是公司硬制度、审批惯例，还是当前职级预算不足。
2. 解释新岗位的价值和职责可能与旧岗位不同，薪酬应基于市场与岗位匹配，而不是只取决于历史收入。
3. 询问是否存在岗位重新定级、特殊审批、长期激励或明确时间点的复议机制。
4. 保持事实一致与职业礼貌，不通过虚构旧薪资或威胁离职争取方案。

**面试验证：** 这个数字的单位、分母、样本量、测量周期和来源分别是什么？

## 9、其他通用面试题（8 题）

### 9-1　一面/二面反问环节可以问业务面试官什么问题？

1. 业务面试官反问应帮助判断岗位目标和实际工作，而不是只问公开网站都能看到的事项。
2. 可问“前六个月最重要的业务结果是什么”“现在主要瓶颈是用户需求、数据还是技术”“产品如何与算法/研发分工”。
3. 进一步问团队如何评估 Agent 效果、推进跨部门决策及判断项目成功。
4. 根据面试中已经谈过的内容选两三个有信息量的问题，避免重复提问或只关注福利。

**面试验证：** 请只讲你本人做的决定和影响，哪些属于团队共同完成？

**原题位置：** https://github.com/zxt6991-source/ai-pm/blob/master/ai-pm-job-interview/ai-pm-job-interview.md#L7594

### 9-2　三面/高管面/VP面 反问环节可以问什么问题？

1. 高管面可以关注战略与经营约束：未来一年产品线最重要的增长假设是什么、企业如何权衡 AI 研发投入与商业回报。
2. 也可问不同客户群的核心价值、组织希望新岗位解决的最难问题，以及对成功的判定标准。
3. 反问应体现你能把技术、产品和商业连接起来，不宜把高管面变成产品细节审查。
4. 根据回答继续追问目标与资源之间的取舍，表现出成熟的经营思考。

**面试验证：** 请只讲你本人做的决定和影响，哪些属于团队共同完成？

**原题位置：** https://github.com/zxt6991-source/ai-pm/blob/master/ai-pm-job-interview/ai-pm-job-interview.md#L7616

### 9-3　你目前面了哪些公司，手上有offer么？

1. 被问面了哪些公司和是否有 Offer，应该如实说明求职进展，但无需披露不必要的公司名称或他人隐私。
2. 可以强调自己的选择标准是岗位职责、发展方向和团队匹配，避免以虚假 Offer 制造谈判压力。
3. 如果确有其他流程，说明时间节奏即可；若没有也无需羞于承认。
4. 把话题引回你为何认真考虑当前岗位以及可以贡献什么。

**面试验证：** 请只讲你本人做的决定和影响，哪些属于团队共同完成？

**原题位置：** https://github.com/zxt6991-source/ai-pm/blob/master/ai-pm-job-interview/ai-pm-job-interview.md#L7630

### 9-4　你有6个月/1年的空窗期，都去做什么了？

1. 有空窗期应按真实时间线解释主要原因，如学习进修、照顾家人、项目尝试或职业调整，不编造在职经历。
2. 展示期间持续进行的具体活动和可验证结果，例如作品、课程成果、真实项目或技能更新。
3. 说明现在为何能够稳定投入新岗位，消除面试官对时间安排和职业方向的担忧。
4. 回答保持简洁，隐私细节无需过度展开。

**面试验证：** 请只讲你本人做的决定和影响，哪些属于团队共同完成？

**原题位置：** https://github.com/zxt6991-source/ai-pm/blob/master/ai-pm-job-interview/ai-pm-job-interview.md#L7648

### 9-5　你对加班怎么看？

1. 对加班的回答应同时体现交付责任和长期效率：关键发布/事故时愿意合理投入，但常态化依赖加班说明流程需要改善。
2. 说明如何通过优先级管理、减少返工、自动化测试和及时识别风险控制无效加班。
3. 也可询问团队真实发布节奏与值班机制，以判断双方预期是否一致。
4. 不要给无法兑现的“随时无限加班”承诺，也避免只回答“坚决不加班”。

**面试验证：** 你实际采取的三个动作是什么？哪个指标证明它们有效？

**原题位置：** https://github.com/zxt6991-source/ai-pm/blob/master/ai-pm-job-interview/ai-pm-job-interview.md#L7676

### 9-6　如果你觉得你的python/sql能力很拉跨，但是面试时又被问到你的水平，你该怎么去圆

1. Python/SQL 不熟悉时，应准确描述当前能独立完成的任务，例如基础查询、聚合统计、数据清洗或借助工具进行分析。
2. 不会的部分明确指出，同时展示正在补足的计划和实际脚本/分析成果。
3. 如果岗位要求较高，可主动准备一个真实案例演示数据提取、清洗、口径核对和结果复验。
4. 不要用“熟悉底层原理”“可以找 AI 生成”掩盖无法理解代码的事实，诚信比临场圆场更重要。

**面试验证：** 你实际采取的三个动作是什么？哪个指标证明它们有效？

### 9-7　HRBP面能反问他什么问题？

1. HRBP 面的反问适合了解组织机制与岗位匹配，例如团队当前阶段、人才发展标准、绩效反馈方式、跨团队协作和入职培养。
2. 可以问“这个岗位前三个月最看重哪几项行为或结果”“优秀同事有哪些共性”“团队如何处理目标变化”。
3. 薪酬与福利可在适当环节询问，但更应关注能否获得达成目标的资源与支持。
4. 问题尽量开放、具体，并结合前面面试中得到的信息继续追问。

**面试验证：** 请只讲你本人做的决定和影响，哪些属于团队共同完成？

### 9-8　如果HR问我有没有再看其他的机会或投其他公司 ，有没有推荐的安全回答？

1. 如果 HR 问是否还在看其他机会，可以如实说明正在正常评估一些岗位或主要专注当前流程，不需列出全部公司。
2. 强调选择工作重视业务方向、职责、成长与双方匹配，不使用虚构 Offer 或不真实的紧迫感。
3. 若有真实时间限制，可礼貌说明需要协调决策窗口，避免给出无法兑现的期限。
4. 保持诚恳、清晰和互相尊重，让对方理解你认真对待当前机会。

**面试验证：** 请只讲你本人做的决定和影响，哪些属于团队共同完成？
